# Надстройка профиля oss-py-fastapi — шаг 7a (Сверщик)

Читать сразу после `core/developer/steps/07a-consistency.md`.

Уточнения к матрице и проверкам:

- Колонка «Контракт» — схема операции **в `openapi/openapi.yaml`** (не в
  сгенерированной Pydantic-модели, которая лишь производная от неё):
  обязательность поля, тип, ограничения, единица измерения. Полнота ограничений
  входа — отдельная проверка по таблице из `02-api-contract.md`: у строки нет
  `maxLength`, у числа — `minimum`/`maximum`, у массива — `maxItems`, у объекта —
  `additionalProperties: false` — это `MISMATCH` контракта, а не стиль. Схема ошибки
  или ответ ошибки, объявленные не в `openapi/common.yaml` (копия), — тоже `MISMATCH`. Сгенерированная
  модель сверяется отдельно на совпадение со спекой (расхождение означает, что
  генератор не перезапускали после правки спеки — `08-generated-code.md`).
- Колонка «Схема/миграция» — `NOT NULL`, тип колонки, `CHECK`, внешний ключ из
  `guidelines/05-db-schema-style.md`.
- Проверка 4 (контракт ошибок, `guidelines/10-errors.md`): у `400` — `$ref: BadRequest`,
  у остальных кодов ошибок нет `content`; каждый код однозначен внутри операции; на
  каждый код есть негативный тест и ожидаемая запись лога (`<операция>_failed` в
  маршруте, техническая — в месте возникновения); в текстах `400` нет SQL и данных
  OSRM/солвера.
- Проверка 5 (типы): сверять с `guidelines/03-data-types.md` — тип поля в контракте
  ↔ тип колонки ↔ тип в Pydantic-модели репозитория ↔ тип в описании теста.
  Отдельно: единицы времени (секунды vs минуты) и представление координат
  (`Point(lat, lon)` в коде против `geometry` в БД).
- **Дополнительная проверка этого стека — типы нигде не проверяет компилятор.**
  `mypy` ловит несовпадение аннотаций, но не несовпадение SQL-типа с Pydantic-
  моделью в динамически собранном объекте (`03-data-types.md`, граница
  репозитория) — эта сверка целиком на шаге 7a.
- Сироты сверять с гайдлайнами: ограничение, требуемое `05-db-schema-style.md`
  (`CHECK`, индекс, комментарий), сиротой не считается.
- Операция, добавленная в `openapi.yaml`, но без прогона `schemathesis` в
  задаче, — сирота контракта: спека утверждена, соответствие ей не проверено.
