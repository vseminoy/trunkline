# Надстройка профиля oss-py-fastapi — шаг 8 (Генератор)

Читать сразу после `core/developer/steps/08-generator.md`.

**Гайдлайны:** стиль — `guidelines/06-code-style.md` и раздел «Требования к коду»
в `AGENTS.md` проекта; работа с БД — `07-aiosql.md`; контракт — `02-api-contract.md`;
сгенерированный код — `08-generated-code.md`; доступ — `04-auth.md`; типы —
`03-data-types.md`.

Уточнения:

- **Спека уже утверждена шагом 5** (`openapi/openapi.yaml`) — этот шаг реализует
  код под неё, а не придумывает контракт по ходу. Первое действие —
  перегенерировать схемы: `datamodel-codegen --input openapi/openapi.yaml
  --input-file-type openapi --output-model-type pydantic_v2.BaseModel
  --field-constraints --use-annotated --output src/api/schemas/generated/`
  (`08-generated-code.md`). Ограничения параметров `query`/`path`/формы в сигнатуре
  роута (`Query(max_length=...)`) переносятся из спеки один в один; своих проверок
  входных данных в теле обработчика нет — их делает FastAPI по моделям
  (`02-api-contract.md`). Файлы под `generated/` руками не редактируются
  (`08-generated-code.md`) — не устраивает форма модели, значит спека неполна,
  и правка идёт туда, а не в сгенерированный файл.
- Проверка инкремента — `commands.build` (`mypy src`) и `commands.lint`
  (`ruff check .`) по изменённым файлам, затем `commands.test_unit`. Компилятора
  нет: опечатка в имени поля обнаружится только типизатором или тестом.
- Порядок написания: `queries/*.sql` → репозиторий (маппинг в Pydantic) → `service`
  → `api` (роут, использующий сгенерированную схему как `response_model`) →
  регистрация роутера в приложении (`app.include_router`). Незарегистрированный
  роутер снаружи недоступен — это забывают чаще всего. Соответствие пути, метода
  и кодов ответа спеке не гарантировано генератором (роуты рукописные) — его
  проверяет `schemathesis` на шаге 7, а не чтение кода на этом шаге.
- Зависимости — только через `Depends(...)` (`06-code-style.md`); `new`-подобных
  глобальных синглтонов для клиента OSRM или пула соединений не заводить.
- Синхронный вызов солвера OR-Tools (`RoutingModel.SolveWithParameters`) — только
  через `run_in_executor`/`anyio.to_thread.run_sync` внутри `async def` обработчика
  или сервиса, не напрямую (`06-code-style.md`).
- Нестандартные паттерны `aiosql`, OR-Tools (`ortools.constraint_solver.routing`) и
  клиента OSRM сверять с официальной документацией, а не с соседним кодом.
- Docstring — только там, где он добавляет то, чего нет в сигнатуре (единица
  измерения, инвариант ограничения, побочный эффект внешнего вызова).
