# Надстройка профиля oss-py-fastapi — шаги 9+10 (Критик и Безопасник)

Читать сразу после `core/developer/steps/09-10-critic-security.md`.

**Гайдлайны (сверять соответствие):** все восемь файлов `guidelines/` плюс
«Требования к коду» из `AGENTS.md` проекта — любое нарушение фиксировать как
Critical/Important. Чек-листы в конце каждого гайдлайна — готовый список проверок,
здесь не дублируются.

**Критик — что не поймает ни один инструмент этого стека:**
- ручная модель, дублирующая схему `openapi.yaml`, вместо сгенерированной
  (`08-generated-code.md`) — ни `mypy`, ни генератор дубликат не запрещают,
  находится только чтением кода;
- роут, не прогнанный `schemathesis` (новая операция в спеке без контрактного
  теста) — генератора, который заставил бы это сделать, нет (`08-generated-code.md`, п. 4);
- `dict`/`Row` из `aiosql`, пересекающий границу репозитория без маппинга в
  Pydantic-модель (`03-data-types.md`, `07-aiosql.md`) — `mypy` этого не увидит,
  пока сигнатура репозитория формально типизирована как `Any` или не типизирована;
- синхронный вызов солвера OR-Tools напрямую в `async def` без `run_in_executor` —
  блокирует event loop, тест на маленьком графе этого не покажет;
- цикл запросов к БД внутри цикла по списку сущностей (N+1) — работает на тестовых
  данных, деградирует на боевом объёме заявок/бригад;
- второй вызывающий изменённого метода — типов, которые ловил бы компилятор в
  языках со статической компиляцией, здесь недостаточно: список вызовов собирается
  поиском по коду явно.

**Безопасник:**
- SQL-инъекции: конкатенация значения в текст запроса вместо именованного параметра
  aiosql (`07-aiosql.md`);
- контроль доступа: есть ли `Depends(current_subject)` и отдельная
  `Depends(require(...))` на изменяющих операциях, нет ли проверки права внутри
  бизнес-логики (`04-auth.md`);
- секреты: ключ подписи JWT, пароли БД, URL внутреннего OSRM — только из
  переменных окружения/`BaseSettings`, не в коде и не в логах;
- размер запроса (`02-api-contract.md`): тело больше `MAX_REQUEST_BODY_BYTES` отклоняется
  до чтения целиком (`413`), `multipart` разбирается с явными пределами; проверка размера
  только на клиенте — не защита;
- ввод без границ (`02-api-contract.md`): строка без `maxLength`, массив без `maxItems`,
  число без диапазона, объект без `additionalProperties: false` — неограниченный ввод
  доходит до сервиса, БД и солвера; ограничение параметра роута расходится со спекой;
- комментарии и docstring (`06-code-style.md`): без ссылок на внутренние документы и
  номера требований, объясняют «почему»;
- ответ ошибки (`10-errors.md`): тело только у `400`, в его текстах нет SQL, трасс,
  путей и данных ответа OSRM/солвера; у остальных кодов тела нет вовсе, в том числе
  у `500` и ответов Starlette;
- логирование ошибок (`10-errors.md`): бизнес-ошибка записана в маршруте с `reason` и
  параметрами, ошибка БД/OSRM — в месте возникновения, без повторной записи выше и без
  персональных данных;
- `pickle`/`eval` над пользовательским вводом, интерполяция ввода в вызов внешнего
  процесса, отключенная проверка TLS у HTTP-клиента к OSRM.
