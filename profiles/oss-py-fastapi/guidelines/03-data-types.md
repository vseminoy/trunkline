# 03. Типы данных

Роль `data_types`. Читают шаги 3, 5, 6, 8.

Задача файла — удержать типы согласованными по всей цепочке:
**БД → результат aiosql-запроса → Pydantic-модель репозитория → сервис → Pydantic-схема
ответа → JSON**. Разрыв в этой цепочке характерен именно для aiosql: он не
генерирует и не проверяет типы сам, в отличие от кодогенератора схем контракта
(`stack.contract.codegen`, см. `07-aiosql.md` и `08-generated-code.md`):

**Граница репозитория — обязательный маппинг, а не проброс.** `aiosql` возвращает то,
что вернул драйвер `psycopg` (`dict`-подобный `Row`), без собственной типизации.
Репозиторий обязан явно собрать из него Pydantic-модель (`EngineerRow.model_validate(dict(row))`
или явный конструктор по полям) **на границе репозитория** — выше по стеку (сервис,
роут) `Row` из aiosql появляться не должен.

**Числа.** Идентификаторы (заявки, бригады) — целочисленный автоинкремент в БД, `int`
в коде, `int` наружу (диапазон в пределах 53 бит JSON-number не превышается на масштабе
задачи — см. `08_algorithm.md`). Координаты — `float` с обязательными границами
(`Field(ge=-90, le=90)` для широты, `Field(ge=-180, le=180)` для долготы). Индекс узла
внутри `RoutingModel` OR-Tools — отдельный `int`, который **не смешивается** с id заявки
или бригады из БД: преобразование индекс↔id — одна явная таблица соответствия в сервисе.

**Время и длительности.** Временны́е окна заявок и рабочее время бригад — `datetime`
с обязательным `tzinfo` (UTC на хранении и в коде; naive `datetime` запрещён); наружу —
строка ISO-8601 с `Z`. Продолжительность (время в пути, время выполнения) — `int`
секунд или `datetime.timedelta` явно; секунды и минуты не смешиваются между слоями —
единица указывается в имени поля (`travel_time_s`) либо в `description` схемы.

**Геометрия.** Координата хранится как `geometry(Point, 4326)` (SRID 4326 = WGS84,
тот же, что отдаёт OSRM). Код выше репозитория (сервис, солвер, ответ API) работает
с ней через одинаковую Pydantic-модель `Point(lat: float, lon: float)`, а не через
`geometry`-представление БД или `ST_*`-выражения — конвертация делается один раз,
в репозитории.

**Пустота.** Отсутствие значения — `NULL` в БД и `None` в коде. Неназначенная заявка
(в OR-Tools — часть `AddDisjunction`) — это `assigned_engineer_id: None`, а не `0` и
не строка `"unassigned"`: две разные пустоты на один смысл дают разные ветвления
в сервисе и на фронте.

## Сводная таблица

| Сущность | Тип в БД (PostgreSQL) | Тип в коде | Тип наружу |
|---|---|---|---|
| Идентификатор | `BIGINT GENERATED ALWAYS AS IDENTITY` | `int` | `number` |
| Координата | `geometry(Point, 4326)` | `Point(lat: float, lon: float)` | `{"lat": number, "lon": number}` |
| Временное окно | `TIMESTAMPTZ` | `datetime` (UTC) | `string`, ISO-8601 `…Z` |
| Длительность в пути | `INTEGER` (секунды) | `int` | `number` (секунды, названо в `description`) |
| Флаг | `BOOLEAN` | `bool` | `boolean` |
| Перечисление (статус заявки) | `TEXT` + `CHECK` | `enum.StrEnum` | `string` |
| Неназначенная заявка | `NULL` в `assigned_engineer_id` | `None` | `null` |

## Чек-лист

- [ ] Ни один `Row` из aiosql не пересекает границу репозитория.
- [ ] Единицы измерения времени и длительности названы явно в имени поля или `description`.
- [ ] Индекс узла OR-Tools не смешивается с id сущности из БД.
- [ ] Геометрия сведена к `Point(lat, lon)` до того, как попала в сервис или ответ API.
- [ ] Сводная таблица покрывает все типы, встречающиеся в задаче.
