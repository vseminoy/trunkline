# 06. Стиль кода

Роль `code_style` (не спрашивается ядром — используется собственными надстройками
шагов профиля, шаги 8 и 9).

**Форматирование и линт.** `ruff` — единственный инструмент форматирования и линтинга
(замена связке `black` + `flake8` + `isort`); конфиг — в `pyproject.toml`. Код,
не проходящий `ruff check .`, в коммит не попадает (`hooks.pre_commit_gate`).

**Типы — обязательны везде.** Каждая функция и метод — с аннотацией параметров и
возврата; `mypy src` в строгом режиме (`disallow_untyped_defs`) — ближайший аналог
сборки в языке без компиляции (`commands.build`). `Any` без обоснования в комментарии
запрещён: это единственное, что заменяет компилятор в этом стеке (см. `09-10-critic-
security.md` — второй вызывающий метода не ловит ничто, кроме поиска по коду и mypy).

**Раскладка.** `src`-layout: `src/api/routes/` (рукописные роутеры),
`src/api/schemas/generated/` (Pydantic-схемы, генерируются из `openapi/openapi.yaml`
и не редактируются, см. `08-generated-code.md`), `src/service/` (бизнес-логика,
включая сборку `RoutingModel`), `src/clients/` (OSRM и другие внешние HTTP-клиенты),
`repository/` рядом со `queries/*.sql` — по слоям из `layers` профиля.

**Внедрение зависимостей.** Только через `Depends(...)` FastAPI: соединение с БД,
HTTP-клиент к OSRM, настройки — каждое через свою фабрику-зависимость с `yield`
(жизненный цикл — `lifespan`/`Depends`), а не через модульный синглтон или глобальную
переменную. Синглтон на уровне модуля нельзя переопределить в тесте без monkeypatch
всего модуля — зависимость переопределяется одной строкой (`app.dependency_overrides`).

**Асинхронность и блокирующие вызовы.** `async def` — для всех обработчиков и
репозиториев, где есть сетевой ввод-вывод или ввод-вывод БД. HTTP — `httpx.AsyncClient`,
не `requests` (синхронный `requests` в `async def` блокирует event loop на весь запрос).
Решение OR-Tools (`RoutingModel.SolveWithParameters`) — синхронный CPU-bound вызов;
вызывать его напрямую в `async def` обработчике запрещено — он блокирует event loop на
время решения (секунды–десятки секунд на объёме задачи). Выносить в
`run_in_executor`/`anyio.to_thread.run_sync`, см. `05-specifier.md` про эндпоинты,
не укладывающиеся в обычный таймаут.

**Комментарии и docstring — короткие, точные, самодостаточные.**
- Комментарий объясняет то, чего не видно из кода: почему так, единицы измерения,
  инвариант, побочный эффект. Пересказ кода — не комментарий.
- **Никаких ссылок на внутренние документы**: имена файлов гайдлайнов, спецификаций и ТЗ
  (`09-logging.md`, `05_spec_backend.md §4.5`), `AGENTS.md`, номера требований (`BR-21`,
  `FR-13`, `NFR-04`), шаги и идентификаторы пайплайна. Комментарий читается без этих
  документов: если причина важна — пишется сама причина, а не адрес, где её искать.
  Ссылка устаревает при переименовании или перенумерации, а читателя отправляет в другой
  файл.
- Ссылки на внешнюю документацию (RFC, issue библиотеки) допустимы, когда без них
  поведение не объяснить.
- То же — для `description` в спеке `openapi/`: её читает клиент API, у которого нет
  внутренних документов.

```python
# ❌
"""The route's path template (e.g. `/tickets/{id}`), not the resolved URL —
keeps path-parameter values out of the access log (`09-logging.md`)."""

# ✅
"""The route's path template (e.g. `/tickets/{id}`), not the resolved URL —
keeps path-parameter values out of the access log."""
```

Проверяется поиском: `grep -rnE '\.md\b|§|AGENTS|\b(BR|FR|NFR)-[0-9]+' src openapi`
не находит ничего.

**Прочее.**
- Логирование — структурированное, `structlog` поверх stdlib `logging`, не `print`
  (правила — `09-logging.md`).
- Настройки — `pydantic-settings` (`BaseSettings`), не `os.environ` вразброс по коду.
- Docstring — только там, где он добавляет то, чего нет в сигнатуре: единицы измерения,
  инвариант ограничения OR-Tools, побочный эффект вызова OSRM.
- `# type: ignore` без комментария, объясняющего конкретную причину, запрещён.

## Чек-лист

- [ ] `ruff check .` и `mypy src` проходят без подавленных предупреждений без причины.
- [ ] Зависимости (БД, OSRM-клиент, настройки) внедряются через `Depends(...)`.
- [ ] Синхронный солвер OR-Tools не вызывается напрямую в `async def`.
- [ ] Комментарии, docstring и `description` спеки — без ссылок на внутренние документы
      и номера требований; объясняют «почему», а не пересказывают код.
- [ ] Сетевые вызовы — `httpx.AsyncClient`, не `requests`.
