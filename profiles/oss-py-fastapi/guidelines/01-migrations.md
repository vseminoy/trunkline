# 01. Миграции

Роль `migrations`. Читают шаги 3 (импакт) и 6 (миграции БД).

**Инструмент — Alembic, без декларативных ORM-моделей.** Одна ревизия = один файл
`alembic/versions/<rev>_<slug>.py` с функциями `upgrade()` и `downgrade()`. Обе функции
пишут **чистый SQL** через `op.execute("...")`; конструкторов `op.create_table` с
типами SQLAlchemy не использовать — источник правды по схеме это сам SQL, а не Python-
объект, который его порождает. Ревизии создаются только командой
`alembic revision -m "<slug>"`: имя файла и `down_revision` руками не пишутся —
разъедется цепочка.

**Единственная целевая СУБД — PostgreSQL 16 + PostGIS.** Ревизии не оглядываются на
другой диалект: `CREATE EXTENSION postgis`, тип `geometry(Point, 4326)`, функции `ST_*`
и `GIST`-индексы пишутся как обычная часть схемы, без диалект-переключателей и без
условной логики по `op.get_bind().dialect.name`.

**Обратимость.** `downgrade()` обязан отменять `upgrade()` полностью и не имеет права
терять данные пользователей. Миграция, откат которой означает потерю колонки с данными,
разбивается на две выкатки: сначала прекращаем писать, следующим релизом удаляем.

**Совместимость с работающим кодом.** Накат схемы и выкатка кода — разные события,
между ними работает старая версия приложения. Одним шагом **запрещено**:

- `ALTER TABLE ... SET NOT NULL` без значения по умолчанию для существующих строк —
  старый код не пишет колонку;
- переименование колонки или таблицы — вместо этого «добавить → двойная запись → удалить»;
- удаление колонки, которую читает выкаченный код или `queries/*.sql`.

**Блокировки.** `GIST`-индекс на geometry-колонке в проде создаётся только
`CREATE INDEX CONCURRENTLY` внутри ревизии с `# transactional_ddl = False`
(`op.execute` не может идти в одной транзакции с `CONCURRENTLY`): обычный `CREATE INDEX`
держит запись на всю таблицу заявок/бригад на время построения индекса.

## Чек-лист

- [ ] Ревизия создана `alembic revision -m`, а не собрана руками.
- [ ] `upgrade()`/`downgrade()` — чистый SQL через `op.execute`, без ORM-конструкторов.
- [ ] `downgrade()` отменяет `upgrade()` без потери данных.
- [ ] Нет `NOT NULL` без значения по умолчанию, переименования или удаления читаемой колонки.
- [ ] `GIST`-индекс на боевой таблице — только `CONCURRENTLY`.
- [ ] Типы колонок согласованы с [03-data-types.md](./03-data-types.md).
