# 04. Авторизация

Роль `auth`. Читают шаги 3, 5, 8 (и шаг 10 при проверке безопасности).

**Где реально проверяется доступ.** Аутентификация — зависимость
`Depends(current_subject)` (`src/api/security.py`), построенная на
`OAuth2PasswordBearer` + JWT (`pyjwt`/`python-jose`): она разбирает `Authorization:
Bearer`, валидирует подпись и срок действия, отдаёт `401` сама через
`HTTPException`. Авторизация (право на конкретную операцию) — отдельная зависимость
`Depends(require("permission"))` на роуте, а не проверка внутри обработчика или
сервиса. Своя аутентификация «на коленке» (ручной разбор заголовка, сравнение токена
в обработчике) не заводится: FastAPI Depends — единственный слой, где это делается.

**Что делает контракт.** Спека (`openapi/openapi.yaml`) **документирует** схему
безопасности (`securitySchemes` + `security` на операции) и не участвует в проверке:
валидатор запросов Pydantic не разбирает токен — иначе аутентификация проверяется
дважды и расходится с зависимостью. Реализация (`Depends(current_subject)` +
`OAuth2PasswordBearer`) держит объявленную в спеке схему в соответствии, но саму
проверку выполняет зависимость, а не сгенерированный по спеке код.

**Разные потребители — разные механизмы.** Пользователь фронта (React) — JWT, полученный
через `/api/v1/auth/token`, с ролью в `payload`; внешняя интеграция (если она есть в
проекте) — сервисный токен в том же заголовке, но с отдельным `scope`. Механизмы не
смешиваются на одном роуте: маршрут объявляет ровно одну зависимость аутентификации.

**Если проект сознательно не делает авторизацию** (например, ограничение технического
задания на объём хакатон-MVP — «без авторизации» — прямое решение продукта, а не
недоделанная часть): это фиксируется явно в `AGENTS.md` проекта одной строкой
(`## Pipeline flags` или отдельный раздел), а не через открытые эндпоинты, у которых
просто нет `Depends(...)`. Отсутствие проверки без явной записи в `AGENTS.md` шаг 9
обязан пометить находкой, а не пропустить молча.

**Секреты.** Ключ подписи JWT, пароли БД, токены внешних сервисов — через переменные
окружения и `pydantic-settings` (`BaseSettings`), не хардкод в коде и не в `Config`-файле
в репозитории.

**Запрещено:** открытый эндпоинт «пока без проверки» без явной записи в `AGENTS.md`;
`require(...)` без аргумента-права; получение субъекта иначе, чем из
`Depends(current_subject)`; проверка права внутри сервиса или репозитория.

```python
@router.patch(
    "/routes/{route_id}/reassign",
    dependencies=[Depends(require("route:replan"))],
)
async def reassign_route(
    route_id: int,
    subject: Subject = Depends(current_subject),
) -> RouteOut:
    ...
```

| Слой | Что делает | Что писать |
|---|---|---|
| `Depends(current_subject)` | аутентификация, `401` | ничего — работает на любом маршруте |
| `Depends(require(...))` | право на операцию, `403` | право в объявлении маршрута |
| Обработчик | берёт субъекта | `Depends(current_subject)` в сигнатуре |
| Сервис / репозиторий | ничего | проверок доступа нет |

## Чек-лист

- [ ] Аутентификация — только через `Depends(current_subject)`, своей нет.
- [ ] Право на операцию — `Depends(require(...))` на маршруте, не в сервисе.
- [ ] Новый маршрут без проверки доступа явно обоснован записью в `AGENTS.md` проекта.
- [ ] Секреты — из переменных окружения / `BaseSettings`, не хардкод.
