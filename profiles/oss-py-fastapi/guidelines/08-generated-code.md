# 08. Сгенерированный код

Роль `generated_code` (не спрашивается ядром — используется собственными
надстройками шагов профиля, шаги 3, 5, 8, 9).

Если Pydantic-модель есть в коде, сгенерированном `datamodel-code-generator` по
спеке (`openapi/openapi.yaml` и файлам, на которые он ссылается, включая
`openapi/common.yaml`), — используем **только её**. Дубль под своим именем не
заводим никогда.

## 1. Запрещено дублировать сгенерированное

Под запрет попадают:
- модели запроса и ответа (`components.schemas` спеки);
- `enum`-типы и константы их значений, объявленные в спеке;
- сигнатура операции (путь, метод, `operationId`) как источник для собственного
  описания — она уже есть в `openapi.yaml`, копия в докстроке расходится при
  правке спеки.

```python
# ❌ ручной дубль схемы, уже описанной в openapi.yaml
class AssignEngineerRequest(BaseModel):
    engineer_id: int

# ✅ используем сгенерированную модель
from src.api.schemas.generated.requests import AssignEngineerRequest
```

## 2. Не устраивает сгенерированный тип — правим спеку

Не устраивает сгенерированная модель (имя поля, формат, обязательность,
`Optional`) — меняем `openapi/openapi.yaml` и перегенерируем
(`datamodel-codegen --input openapi/openapi.yaml --input-file-type openapi
--output src/api/schemas/generated/ --output-model-type pydantic_v2.BaseModel
--field-constraints --use-annotated`), а не правим сгенерированный файл руками: следующая
перегенерация правку молча затрёт, и расхождение обнаружится не сразу.

Ограничения спеки (`maxLength`, `pattern`, `maximum`, `maxItems`) генератор переносит в
сгенерированную модель, и FastAPI проверяет их до вызова обработчика
(`02-api-contract.md`, «Валидация входных данных»). `--field-constraints` и
`--use-annotated` выражают их как `Annotated[str, Field(max_length=...)]` вместо типов
`constr(...)`/`conlist(...)`: ограничение видно в модели, и `mypy` понимает тип поля.

## 3. Сгенерированные модели ходят вглубь

Сгенерированные модели передаются в `service` как есть на границе API. Собственные
доменные модели заводятся только там, где у слоя действительно другая форма данных
(например, внутреннее представление узла OR-Tools, которого нет в контракте) — и
тогда это осознанная конвертация на границе слоя, а не копия схемы контракта.

## 4. Роуты — не генерируются

В отличие от моделей, `APIRouter`-обработчики пишутся руками: генератора, который
безопасно сочетал бы сгенерированный по спеке роутинг с зависимостями FastAPI
(аутентификация, сессия БД, сервис), в экосистеме нет. Соответствие обработчика
спеке (путь, метод, коды ответов) удерживают контрактные тесты `schemathesis`
(`steps/07-tester.md`), а не генератор — это единственное место в профиле, где
конформизм со спекой не гарантирован инструментом и требует явной проверки на
шаге 9.

## 5. Сгенерированное видно по расположению

Сгенерированные модели лежат только в `src/api/schemas/generated/` — файл вне
этой директории не может быть результатом `datamodel-code-generator`, и наоборот,
всё в этой директории перезаписывается при перегенерации и не редактируется.

## Чек-лист

- [ ] Нет ручных моделей, повторяющих схемы `openapi.yaml`.
- [ ] Изменение формы данных контракта сделано в спеке и перегенерацией, а не
      правкой файла в `src/api/schemas/generated/`.
- [ ] Сгенерированные модели используются в `service` напрямую, без конвертации
      «на всякий случай».
- [ ] Ничего вне `src/api/schemas/generated/` не выдаётся за сгенерированное и
      наоборот.
- [ ] Новый или изменённый роут проверен `schemathesis`, а не только вручную.
