# Гайдлайны профиля oss-py-fastapi

Свод обязательных правил для бэкенд-сервисов на FastAPI + aiosql + Alembic. Это
**источник правды** по контрактам, миграциям, типам и авторизации. Агенты пайплайна
обязаны сверяться с этими файлами начиная с **Шага 3 (Импакт-Аналитик)** и далее на всех
шагах, где это применимо (см. блоки «Правила профиля» в шагах ядра).

У профиля нет корпоративного владельца стандартов — правила ниже общепринятые практики
экосистемы FastAPI/aiosql, а не чей-то внутренний регламент (отсюда префикс `oss-`
в имени профиля вместо имени организации).

Ядро на эти файлы по именам не ссылается — только по ролям из `profile.yaml`
(`api_spec`, `migrations`, `data_types`, `auth`, `db_schema_style`). Роли `code_style`,
`db_access`, `generated_code`, `logging` и `errors` ядро не спрашивает — они используются только
собственными надстройками шагов этого профиля.

Разработка — контрактная (spec-driven): контракт (`openapi/openapi.yaml`) пишется
и утверждается на шаге 5, до кода, а не выводится из него постфактум — см.
[02-api-contract.md](./02-api-contract.md) и [08-generated-code.md](./08-generated-code.md).

## Приоритет

При конфликте источников приоритет такой:
**`AGENTS.md` проекта → гайдлайны профиля → ядро → персональные предпочтения агента.**
Правила нейминга сущностей (глоссарий) сюда **не входят** — за этим следит разработчик.
