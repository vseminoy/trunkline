# 03. Типы данных

**Скелет.** Роль `data_types`. Читают шаги 3, 5, 6, 8.

Задача файла — удержать типы согласованными по всей цепочке: **контракт ↔ код ↔ БД ↔ клиент**.
Описать здесь:

- **Цепочку целиком** и что в ней настраивается, а не выбирается (конфиг генератора,
  режим nullable, переопределения типов).
- **Числа** — какие ширины используются, где нужен явный формат, что происходит без него.
- **Границу с клиентом** — что нельзя отдавать числом (идентификаторы и суммы, не влезающие
  в 53 бита) и где делается конвертация.
- **Даты** — тип в БД, тип в коде, часовой пояс, формат обмена.
- **Пустоту** — как выражается отсутствие значения и что запрещено (две разные пустоты
  на один смысл).

Заканчивать **сводной таблицей** «сущность → тип в БД → тип в коде → тип наружу»: агенты
пользуются ею чаще, чем прозой.

## Как это выглядит заполненным

Пример на демо-стеке профиля (Python 3.12, SQLAlchemy 2.0, PostgreSQL). Заменить на свои.

> **Цепочка.** PostgreSQL → SQLAlchemy `Mapped[...]` → Pydantic-модель → JSON.
> Типы задаются в SQLAlchemy-модели явным `Mapped[int]` / `mapped_column(BigInteger)`;
> автовывод типа по значению по умолчанию не используется — он молча меняется
> при смене значения.
>
> **Числа.** Идентификаторы — `BIGINT` в БД и `int` в коде. Денежные суммы —
> `NUMERIC(19, 4)` в БД и `decimal.Decimal` в коде; `float` для денег **запрещён**
> на всех слоях, включая промежуточные расчёты.
>
> **Граница с клиентом.** Всё, что не влезает в 53 бита JSON-number, отдаётся **строкой**:
> идентификаторы (`BIGINT`) и суммы (`Decimal`). Конвертация делается один раз —
> в Pydantic-модели ответа (`field_serializer`), а не в обработчике и не на фронте.
>
> **Даты.** В БД — `TIMESTAMPTZ`, в коде — `datetime` с обязательным `tzinfo=UTC`
> (naive `datetime` запрещён), наружу — строка ISO-8601 в UTC с `Z`.
> Только дата без времени — `DATE` / `datetime.date`.
>
> **Пустота.** Отсутствие значения — `NULL` в БД и `None` в коде. Пустая строка как
> «значения нет» запрещена: две разные пустоты на один смысл дают два разных запроса
> и расходящиеся отчёты. Отличать «поле не передано» от «передано null» — только
> через `model_fields_set` в PATCH-моделях.

### Сводная таблица

| Сущность | Тип в БД | Тип в коде | Тип наружу |
|---|---|---|---|
| Идентификатор | `BIGINT` | `int` | `string` |
| Денежная сумма | `NUMERIC(19,4)` | `Decimal` | `string` |
| Количество | `INTEGER` | `int` | `number` |
| Момент времени | `TIMESTAMPTZ` | `datetime` (UTC) | `string`, ISO-8601 `…Z` |
| Календарная дата | `DATE` | `date` | `string`, `YYYY-MM-DD` |
| Флаг | `BOOLEAN` | `bool` | `boolean` |
| Перечисление | `TEXT` + `CHECK` | `enum.StrEnum` | `string` |
| Отсутствие значения | `NULL` | `None` | `null` |
