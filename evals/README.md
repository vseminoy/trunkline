# Evals собственных скиллов

Проверка скиллов этого репозитория (`core/analytic/skills/`, `core/skills/`) —
теми же правилами, по которым `agent-skills` проверяет свои.

| Tier | Что проверяет | Команда |
|---|---|---|
| 1. Структурный | frontmatter, `name` = каталог, обязательные секции, мёртвые кросс-ссылки | `node scripts/lint-own-skills.js` |
| 2. Trigger & routing | целевой скилл попадает в top-k по своему промпту, не перехватывает чужие, описания не сталкиваются | `node scripts/run-own-evals.js` |

Оба скрипта возвращают код 1 при ошибках — годятся как гейт в CI.

## Почему свои раннеры, а не апстримные

- `agent-skills/scripts/validate-skills.js` жёстко смотрит только в собственный `skills/`.
- `agent-skills/scripts/run-evals.js` токенизирует `[^a-z0-9\s-]` → пробел: кириллица
  выбрасывается целиком, все наши документы получаются пустыми. В `run-own-evals.js`
  тот же алгоритм (TF-IDF по `name`×2 + `description`, косинус), но с Unicode-токенизацией
  и грубым стеммером для русского.

Известное подавление: Tier-1 требует английского «Use when …» в описании. Наши описания
говорят «Использовать, когда …», поэтому это срабатывание глушится — счётчик подавлений
печатается, чтобы подавление оставалось видимым.

## Кейсы

`evals/cases/<имя-скилла>.json` — по файлу на скилл, имя файла обязано совпадать
со `skill_name`. Формат — подмножество схемы апстрима:

```json
{
  "skill_name": "decompose-from-scratch",
  "trigger": {
    "positive": [{ "prompt": "…как это скажет пользователь…", "top_k": 3 }],
    "negative": [{ "prompt": "…чужая задача…", "owner": "review-and-complete-tasks" }]
  }
}
```

- **positive** — скилл обязан войти в top-k. Формулировать так, как реально пишет
  пользователь, а не переписывать `description` своими словами: иначе тест проверяет
  сам себя.
- **negative** — скилл обязан **не** занять top-1. `owner` (необязателен) — кто должен
  выиграть; расхождение даёт warning, а не ошибку.

Tier 2 — лексическое приближение маршрутизации, не семантика. Он ловит два
доминирующих класса реальных багов триггеров: описание без слов, которыми говорит
пользователь (ложный отрицательный), и слишком широкое описание, перебивающее нужный
скилл (ложный положительный). Провал обычно означает «исправь `description`»,
а не «исправь кейс».

Корпус для ранжирования включает **и 24 скилла из `agent-skills`** как конкурентов —
в реальной сессии агент выбирает из всех сразу. Кейсы для них не нужны, и коллизии
внутри апстримного каталога не проверяются.
