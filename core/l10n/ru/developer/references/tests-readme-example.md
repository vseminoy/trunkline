# Эталон `tests_readme.md`

Образец формата описания тестов для шага 7 (Агент-Тестировщик). Копировать структуру,
не содержание: домен здесь вымышленный (платежи), важны разбиение по слоям, блок моков,
колонки таблицы и прослеживание пути ошибки.

Обязательные элементы и то, что блокирует шаг, перечислены в
`core/developer/steps/07-tester.md` и здесь не повторяются. Этот файл показывает, как они
выглядят в написанном виде.

Имена в образце — заглушки. Конкретные имена файлов берутся из `layers[]` профиля
(`test_file`), значения ошибок — из стека, соглашение об именовании тестов — из надстройки
профиля к шагу 7. Профиль может добавить свой экземпляр этого формата в надстройку; сам
формат фиксируется здесь.

Всё после разделителя копируется как шаблон.

## На что смотреть при копировании

**Путь ошибки прослеживается по слоям.** Одно и то же нарушение видно на трёх уровнях:
«строк нет» (запрос) → `ErrNotFound` (сервис) → `404` без тела (HTTP-слой). Если по таблицам
нельзя проследить, во что превращается ошибка, описание неполное.

**Тела ответов — по контракту.** Какие коды имеют тело и в каком виде, фиксирует роль
`api_spec` профиля — не угадывается. В `Ожидаемый результат` это пишется явно: «тела нет»
так же важно, как «тело с …».

**Идентификаторов правил в этом файле нет.** Документ коммитится и живёт дольше прогона, который
его написал, а реестр правил удаляется вместе с прогоном — колонка `Правило` или раздел покрытия
оставили бы будущему читателю номер, за которым ничего нет. Какое правило покрывает тест,
записывается в карточку покрытия прогона под `.pipeline/workdir/coverage/`; здесь сценарий должен
читаться из самого сценария.

**Одно правило — минимум один тест, обычно два.** Проверка на слое, где правило принуждается,
плюс проверка кода ответа на HTTP-слое. Правило без теста — блокер шага 7, и проверяется это
по карточке покрытия.

**Документ организован только по слоям.** Ни один раздел, таблица или примечание не называется по
ченджсету, и нигде не пишется, что описание пополняется по ченджсетам. Следующий ченджсет дописывает
свои строки в уже существующие таблицы слоёв — файл всегда читается как текущее состояние тестов
модуля, а не как хронология их написания.
