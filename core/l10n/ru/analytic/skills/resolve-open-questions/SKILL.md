# Сценарий C: закрытие открытых вопросов

## Overview

Декомпозиция редко завершается «вчистую»: остаются вопросы к продукту/команде,
неподтверждённые предположения и задачи с `ready: false`. Этот сценарий — управляемый
возврат к таким задачам: пройти **реестр открытых вопросов** из состояния, по каждому получить
ответ (от пользователя или из кода), принять решение, **обновить затронутые задачи** и снять
гейт готовности там, где блокер ушёл. Цель — довести задачи до `ready: true`.

Режим — только чтение по коду; файлы задач изменяются только с согласия пользователя.

## When to Use

- Задачи уже написаны (через A или B), состояние содержит непустой реестр открытых вопросов.
- Есть задачи с `ready: false` или неподтверждённые ASSUMPTIONS, блокирующие заведение в JIRA.
- Пользователь вернулся с ответами на ранее заданные вопросы.

**When NOT to use:** задач нет → `decompose-from-scratch`; задачи есть, но не
проверены/не оценены → `review-and-complete-tasks`.

## Process

В начале — загрузить состояние (`analysis-state`, сценарий = C). Если состояния нет — открытые
вопросы собрать прогоном `review-and-complete-tasks` и только потом закрывать.

### 1. Свести открытые пункты `[STOP]`
Из состояния собрать всё незакрытое: открытые вопросы (`Q*`), неподтверждённые ASSUMPTIONS,
задачи с `ready: false`. Для каждого указать, **какие задачи он блокирует**. Приоритизировать:
сначала вопросы, блокирующие фундаментные задачи (контракт, схема, миграция).

### 2. Закрыть каждый вопрос `[STOP]` (по одному)
Для каждого вопроса:
- сформулировать его конкретно и показать, что от ответа зависит;
- получить ответ: **уточнить у пользователя** (Manage Confusion: 2–3 варианта) или
  **проверить в коде** (Verify Don't Assume — `grep`/`Explore`, читать, не угадывать);
- зафиксировать **решение** и его последствия для задач.

Если ответ порождает новую работу, не покрытую задачами, — это **новый пробел**: завести
задачу (как в `review-and-complete-tasks`, шаг 5) или новый открытый вопрос, не теряя его.

### 3. Обновить затронутые задачи `[STOP]`
По принятым решениям отредактировать тело/`links`/front-matter затронутых задач (строго по
спеке формата). Если объём решения изменил оценку или превысил 24 ч — вернуть к дроблению.
**Правки — только с согласия пользователя.**

### 4. Снять гейт готовности `[STOP]`
Для задач, у которых все блокирующие вопросы закрыты и блокеры (`links`) разрешимы,
перевести `ready: false → true`. Задачи с оставшимися открытыми вопросами оставить
`ready: false` — они не заводятся в JIRA, пока не готовы.

### 5. Обновить состояние и журнал `[STOP]`
В реестре пометить вопросы `закрыт` с записанным ответом. В «Журнал решений» внести, что
изменилось. Пересчитать «Следующее действие»: что ещё открыто, или «все вопросы закрыты,
эпик готов к заведению». **Выход:** обновлённые файлы задач + состояние + сводка по закрытым
вопросам и оставшимся блокерам.

## Common Rationalizations

| Рационализация | Реальность |
|---|---|
| «Поставлю ready=true, потом разберёмся» | `ready=true` заведёт задачу в JIRA. Снимать гейт только после реального закрытия блокера. |
| «Вопрос мелкий, отвечу сам» | Если ответ влияет на поведение/контракт — это решение пользователя/команды. Спросить. |
| «Ответ не меняет задачи» | Проверить явно: ответ часто меняет тело, оценку или `links`. |
| «Новый вопрос всплыл — потом запишу» | Незаписанный вопрос теряется. Сразу в реестр состояния. |

## Red Flags

- `ready` переведён в `true` при незакрытом блокирующем вопросе.
- Вопрос «закрыт» в состоянии без записанного ответа/решения.
- Решение принято без проверки кода или без согласия пользователя по правке файлов.
- Новые пробелы, всплывшие при ответах, не превращены в задачи/вопросы.
- Состояние не отражает, что осталось открытым после сессии.

## Verification

- [ ] Все открытые вопросы состояния рассмотрены; по каждому — ответ или явный статус «остаётся открытым».
- [ ] Затронутые задачи обновлены по спеке формата с согласия пользователя.
- [ ] `ready` снят только там, где блокеры реально закрыты; оценки пересчитаны при необходимости.
- [ ] Реестр вопросов и журнал решений в состоянии актуальны; «Следующее действие» обновлено.
- [ ] Новые пробелы заведены как задачи или открытые вопросы, не потеряны.
