## 1. С чего начали (проблема)

Универсальные SDD-фреймворки дают процесс и оставляют доменные правила в голове
разработчика. На брownfield-проекте это ломается предсказуемо:

- агент начинает с кода и приносит diff, который надо читать целиком;
- каждая задача пересобирает AS-IS с нуля — контекст стоит дорого и каждый раз заново;
- правило из постановки теряется по дороге до кода, и никто этого не замечает.

‹Один абзац про конкретный проект: язык, размер кодовой базы, сколько человек, какой
цикл поставки. Без имени сервиса.›

## 2. Что построили

Ядро (стек-агностичный процесс) + профиль (язык, команды, гайдлайны). Ядро ссылается
на правила по ролям, а не пересказывает их: дополнили гайдлайн — пайплайн не меняется.

Три механики, ради которых всё делалось:

1. **Трассируемость `R-<прогон>-<n>`.** Правило получает идентификатор один раз и проходит
   с ним спеку, схему, тесты, код и сообщение коммита — включая границу между
   аналитиком и разработчиком, где раньше цепочка рвалась всегда.
2. **Шаг 7a.** Блокирующая сверка четырёх артефактов между собой.
3. **База знаний `.pipeline/knowledge/`.** Вторая задача по модулю дешевле первой.

## 3. Ключевой момент: дефект, который поймал шаг 7a

Это центр рассказа — конкретный случай, а не описание механики.

‹Взять реальный случай из `consistency.md`. Нужны: формулировка требования,
что именно разошлось (значение в спеке vs в схеме vs в тесте), почему тест был
зелёным, и сколько это стоило бы, если бы уехало в прод.›

Форма, в которой это читается лучше всего:

```
Требование:  ‹формулировка›
В спеке:     ‹что стояло›
В схеме:     ‹что стояло›
В тесте:     ‹что проверялось›
Статус 7a:   РАСХОЖДЕНИЕ → возврат к шагу ‹N›
```

Мораль абзаца: зелёный тест доказывает, что код делает то, что написано в контракте.
Он ничего не говорит о том, попало ли в контракт требование.

## 4. Цифры

Из `.pipeline/workdir/metrics/pipeline.jsonl` за ‹N› слайсов:

| Что | Значение |
|---|---|
| Слайсов пройдено | ‹N› |
| Шаги, нашедшие дефекты | ‹7a: N пробелов, 9: N Critical, 10: N High› |
| Шаги без единой находки | ‹список› |
| Самая частая точка отката | ‹7a → 5, N раз› |
| Переиспользовано контекста из базы знаний | ‹N%› |
| Находок `STALE` | ‹N› |
| Средняя стоимость слайса | ‹N подтверждений, N откатов› |

‹Если по данным какой-то шаг ни разу ничего не нашёл — сказать об этом прямо
и написать, что с ним сделали. Кейс, где процесс сам себя сократил по данным,
убедительнее кейса, где всё оказалось полезным.›
